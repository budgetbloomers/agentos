## Item 5 — TL notifications (Aarav)

Constraint: Cloudflare Worker FREE plan (50 subrequests, 10 ms CPU) — never poll HighLevel per TL.

Design (revised after the architect review — see "Review changes" below):
- EVERY ask — first-ever cards included (help.mjs ~254, which writes no record today) — writes
  `kv:help-card:<id>` with `{cb, asked_at, acknowledged_at:null, completed_at:null, …}`. A repeat ask RESETS
  acknowledged/completed (the reuse path copies the old record forward, help.mjs ~216, which would hide a
  repeat ask behind an old "seen"). Store the CB, NOT the team — a stored team goes stale for movers (Denise's
  UAT agents) and re-spelt leaders. Backfill cb on the existing card rows.
- `GET /api/portal/help/pulse` → `{unread, latest:{agent, topic, at}}`: session + `loadDigest` (60 s cache) +
  ONE prefix read of `kv:help-card:*`, filtered by `authorise().codes` — ≤ 5 subrequests, scoped exactly like
  the list, no PostgREST JSON filter. TL scope; agent → 403; added to PORTAL_ALLOWED. A campaign manager's
  badge counts the Campaign Assistance queue (`kv:cm-areq`), not agents' asks — decide the CM half explicitly.
- Only the agent's OWN team leader stamps "Seen by"; an admin/exec opening the card does not.
- The toast links into `helpList`, which reads HighLevel's lagging search index — merge in card ids from
  `kv:help-card` that the search has not returned yet, or the request "isn't there" when the TL clicks.
- Agent Analytics (TL view, same skin): **one icon with the unread count on the Help Center nav item**
  (D5 — no toast, no page-title count, no browser notification, no email/SMS). Poll every 20 s while
  visible and at once on focus; stop when hidden. Opening the request clears it and stamps "Seen by".
Acceptance: an agent's ask shows on the TL's open screen within 20 s without a click (Playwright, two
browser contexts). Tests + ecc:security-reviewer on `/pulse`.

## Item 1 — Leave / attendance (Ryan)

**Cause (code map).** The HR attendance register is parsed (`INGEST.attendance`, nicks_code/index.html
~2513) and the leave code arrives (`AL` — "Annual leave" — seen in the Sept register fixture). But:
- `attWeights` (~554) gives `AL: 0` — the same as an unplanned absence (CA/UCA); the rule book agrees
  (`specs/mtd_engine_rules.json` `attendance_shift_weights`, ~399–425). Nothing says leave is excused.
- The fact builder (~4303) keeps `emp = 1` on a leave day, so the **target grows** (`target = perDay × emp`,
  ~4385) and **Attendance % falls** (act ÷ emp, ~4565). SPD is unaffected.
- `dataOnlyDay()` (~4090) is floor-wide (Saturdays, public holidays); there is no per-agent equivalent.
- The digest carries only `emp`/`act`, so Agent Analytics cannot tell leave from absence.
- Ops (`Chatterbox_AgentOS_Analytics.html` ~3945/4181) knows `leaveCodes` but still counts them as
  scheduled — an agent on leave all window fires **R1 "Zero Attendance – escalate to HR"** and R3.

**Proposed rule (DECISION D1 for Nick).** An *excused* status makes that agent-day "data, not a shift" —
exactly how Saturdays and public holidays already work, but per agent: `emp = 0, act = 0`, sales that day
still count; target pro-rated; Attendance and SPD untouched. Effective-dated from 2026-09-01 so August's
workbook-verified figures never move. Rule + dated `_changes[]` in the spec and the inline `MTD_RULES`
together (`verify-engine-rules`). Which codes are excused: **AL** certainly; SL (sick), FRL (family
responsibility) are statutory — Nick decides. CA/UCA stay absences.
Also: the digest gains a per-agent leave count and a per-day status (working | leave | absent | off) so the
agent card says "3 days annual leave — not counted" and no recommendation fires for a leave day; Ops
excludes leave codes from `sched`. New guard `verify-leave-days.mjs`; keep `verify-saturday-rule`,
`verify-public-holidays`, `verify-engine-rules`, `verify-agent-card` green. Needs from Denise: the agents
and dates that were wrong in UAT, to use as the fixture.

## Decisions (29 Sep 2026 — decided by Aarav for Nick; Nick to confirm)

The questions were D1–D5 above. Answers as built into the later prompts; each rule that touches the rule book
still lands there with its own dated `_changes[]` entry when it is built.

- **D1 Leave.** Each agent-day is *working | leave | absent | unavailable*, from ONE code list shared by
  PULSE and Ops. **Leave (excused): AL, SL, FRL**; HDAL = half an excused day. **Unavailable (excused):
  Suspended.** **Absence: CA, UCA** — Ops' `leaveCodes` (which call CA "Committed Absence (authorised)")
  are aligned to this, in the same release. An excused day with NO talk and NO sales leaves the Employed
  count (target pro-rated; Attendance and SPD untouched); an excused day WITH activity keeps its shift and is
  flagged. Effective from 2026-09-01 — August's workbook-verified figures never move.
  *Why SL is excused:* the spec §5 note on CB143 (sick leave all period, "IS included") is about the
  reference tracker's HEAD COUNT, not a rule that sick leave is an absence. Honoured: an agent on leave for
  the whole period stays in the head count and the digest, shown as "on leave" with no target.
- **D2 Last updated for agents.** One quiet line under the header — "Figures to <last data day> · updated
  <HH:MM>" — no freshness card or dot (the 3 Sep "no data-assurance chrome" stays true for everything else).
  The agent card re-fetches on focus and every 5 minutes while visible.
- **D3 TL help recommended.** A KPI recommends asking the team leader when it is below target month-to-date
  AND either (a) it was below target in ≥ 3 of the last 5 sessions, or (b) closing the gap needs more than
  1.5× the agent's current daily pace over the working days left. A QA compliance/verification fail always
  recommends it. The 3-of-5 and 1.5× thresholds live in a spec file with a dated `_changes[]` entry — never
  in the page.
- **D4 Campaign split.** A mover's month is split by date: the overall row is the SUM of every campaign
  (also fixing `primaryAgg`, which publishes one campaign), plus one row per campaign with its date span.
  The latest Agent List still decides the campaign NOW and the team leader. **Move date:** the first Agent
  List showing the new campaign, sharpened by the tracker daily sheet where it states the day, with a
  per-agent "effective from" override at upload. For September: check `kv:roster-refused` and the refused
  10–14 Sep uploads first; default to 14 Sep for CB121/150/162/245, flagged for Denise to confirm.
  **Commission:** each campaign's days on its own plan, brackets pro-rated by days, shown as a labelled
  projection — **needs Nick/finance sign-off before anyone is paid on it.**
- **D5 TL notification (decided by Aarav).** One icon with a count on the Help Center tab tells the team
  leader someone asked for help. No pop-up, no browser notification, no email/SMS. It clears when the team
  leader opens the request — which also stamps "Seen by" (Nick's step 4). Item 5's design shrinks to the
  icon + `/api/portal/help/pulse`.
