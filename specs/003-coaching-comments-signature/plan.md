# Implementation Plan: Coaching comments show, signatures save

**Branch**: `003-coaching-comments-signature` | **Date**: 2026-10-05 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/003-coaching-comments-signature/spec.md`

## Summary

Two confirmed defects in the team leader's Coaching Hub tab (Agent Analytics → Worker → Convex Coaching Hub):
(1) the signature pad is wired with the form's READER in the setter's place, so no drawn signature ever reaches the
save — fix the call site, make drawing mark the form dirty, refuse (never drop) a malformed signature in the Worker,
and have the session list state which signatures each record holds (presence only — no images, which also closes a
nested-image leak on group sessions); (2) Formal Coaching comments are stored but every summary reads field names
that product does not have — add product-keyed note/said/agreed helpers on the page and carry the formal call notes
(never the customer contact numbers) in the coaching copy. A read-only tool lists the sessions already saved unsigned
so they can be re-signed in the Hub app.

## Technical Context

**Language/Version**: ES5 page (`agent/index.html`); ESM Worker (`worker/src`); Node 24 tools.

**Primary Dependencies**: Cloudflare Workers + Pages; Convex Coaching Hub (the live list + create through the
existing proxy; read-only for the audit tool).

**Storage**: none new — `kv:coaching` copy gains `callNotes` per formal session.

**Testing**: new `nicks_code/diagnostics/verify-coaching-signature.mjs` (page in a stubbed DOM + Worker modules with a
stubbed `fetch`), written first and registered in `.github/workflows/verify.yml`; existing coaching/page suites rerun.

**Target Platform**: Cloudflare FREE plan (10 ms CPU, 50 subrequests) — no new subrequests: the list and create paths
make the same Convex calls as today.

**Project Type**: web application (give-out page → Worker proxy → external Hub).

**Constraints**: signatures never reach a browser or the copy; customer contact numbers never reach an agent payload;
nothing writes to the live Hub during development or testing.

**Scale/Scope**: 23 Hub team leaders, ~1,400 sessions; 3 records known unsigned from the new view.
