## Non-negotiables (violating these is a bug)

1. **NBA math is deterministic code, never LLM arithmetic.** The dashboard's `acStats`/`cfTier`/`acNBA`/`acComposite` functions are the engine. Agents may EXPLAIN scores; only code COMPUTES them. When scoring outside the dashboard, write and run a script.
2. **One primary NBA per agent** — ladder walked in fixed order P1·R1 → P4·R10, first trigger wins. R2A-1 is a flag/footnote, never a primary NBA.
3. **R2A tier = HIGHER of count band and rate band.** One capped penalty per tier (`pen1`/`pen2`/`pen3` in the `nbaThresholds` rule — live-editable; the cap is `pen3`). Never the retired −3-per-*fail* v2.5 logic: the penalty is a tier value, never accumulated per fail.
4. **Composite is the `compositeWeights` rule** — Value/Volume/QA/GWP %ile/Conversion/Talk/Attendance, in that priority order (value first, then volume, then quality); weights are live-editable and renormalise across the metrics an agent actually has. Penalty applied AFTER the sum ('Adj'). Cancellations and attempts-per-lead are diagnostics — never scored.
5. **Tenure-relative everything.** Never compare agents across tenure groups (M1/M2/EXP–Courtesy/EXP–Cuddle). GWP percentile within group only.
6. **One money model: Power BI - Active Cases** (specs/AgentOS-v3.8-upload-frameworks.md §2). GWP = Σ Charge Amount per account, charges are EX-VAT, grossed up ×(1+vatRate rule, default 15%, zero-safe) to inclusive; sale dated per row's Contract Create Date; agent matched on Owner. Monthly uploads ACCUMULATE — a re-upload replaces only its own date span (deliberate deviation from pack R-ING-BI-06). There is NO legacy fallback: with no BI file loaded, money reads blank and says so. The old Activated-Services + GWP-table pricing was removed 2026-07; never reintroduce it silently. **An absence is not a nought, and this now runs the whole way through the scoring**: with no BI file, `acStats` returns null (not 0) for Target Achievement, Conversion and sales-per-day, `applyGroupPercentiles` returns null for the GWP percentile, and `acComposite` renormalises across the metrics the agent actually has — so no team's composite silently drops ~30 points and the NBA ladder does not report a floor-wide "Critical Sales-Volume Failure" over a missing upload. An agent who genuinely sold nothing WITH a BI file loaded still scores 0 and still fires the ladder. Guarded by `diagnostics/verify-ops-no-bi.mjs` (10 checks, both directions). The same doctrine governs PULSE's `perfScore`: a driver with no data leaves the denominator and the rest renormalise to 100 — never an imputed value (QA used to be filled in at 80%, so an agent evaluated at a real 70% ranked below one nobody had evaluated) and never a zero. A real 0% QA still scores zero, because the rule book is explicit that a zero is an outcome. `perfParts` publishes the EFFECTIVE weight, so Agent Analytics' rating card still adds up. Guarded by `diagnostics/verify-perf-score.mjs` (10 checks).
7. **CB codes normalise**: `CB-15` = `CB15` = `cb 15` (see `normCB`). The daily Agent List is the identity base — every cross-source join resolves through it. Unmapped rows are FLAGGED, never silently dropped or invented.
8. **KB response contract**: label every figure actual/model/proposed/historical; `[INPUT REQUIRED]` for missing facts, never invent; flag conflicts (330 vs 370 agents, R42,500 vs R34,762 rev/agent, etc.) per module 10 treatments; never call seat contribution "EBITDA" before management-account tie-out.
9. **Names**: Nicholas Pillay = CTTO (never "Chief Growth..."); Claudell Panday (spelling); Abigail owns recruitment execution; COO unresolved unless kb-state.md records signed evidence.
10. **PII**: masking defaults ON. The suite sits behind its own login (worker/src/auth.mjs — PBKDF2 + sessions + lockout; auth-gate.js on every page). Cloudflare Access remains an optional outer wall, not the only lock.
11. **History is attributed to the org as it stood — at MONTH grain, and the Agent List owns the current month.** Facts read `orgAt(code, date)` — the effective-dated `S.orgHist` — never `S.roster`, which is a live snapshot with no effective date and so is the wrong answer for every past day. **The list wins its whole month (Nick, 2026-08-27, third request: "when the agent list is updating, it needs to update all the time"):** a roster ingest calls `recordOrgList`, which REWRITES the agent's segments inside the list's own month (segment lands on the month boundary; a new intake keeps their first-sighting date) and leaves every other month — earlier AND later — untouched, so a mover reads the new TL/campaign for the whole current month the moment the list lands. Cross-month attribution is unchanged: Month 1 keeps its leader when the agent moves in Month 2. The tracker daily sheet still files day-dated history through `recordOrg`; a later list collapses it only within its own month. A snapshot is stamped with the date it describes (`rosterAsOf`: the Data tab's "effective from", else a date in the filename, else today) — the override now picks WHICH month the list wins. Dates before the earliest observation resolve to that earliest segment. Placeholder carve-outs survive: a "TBC"/blank TL never erases a real leader, and a first REAL assignment back-dates over an all-placeholder history (`provisionalTL`). `M.agents[].tl` is the period's leader and `tlNow` the current one; `M.tlMoved` names the difference (now only cross-source/cross-month). Guarded by `diagnostics/verify-history.mjs` (39 checks) + `verify-tbc-backdate.mjs` (9). The Agent List also SYNCS across apps: uploads land in the VAS Upload Station; the Worker's `/api/roster` serves PULSE's roster with a change-fingerprint, and AgentOS Analytics re-ingests it through its own `applyLoad` on boot + every 10 min (`syncRosterFromVAS`) — never edit one app's roster store by hand. Every OTHER export relays as the RAW FILE, never derived rows (PULSE aggregates at ingest, so derived rows would strip QA coaching categories / per-call rows / BI charge detail), and the relay is BIDIRECTIONAL — an upload in EITHER station reaches the other app: PULSE's `archiveUpload` and AgentOS's `archiveForVAS` post ingested bytes to the Worker (`/api/upload-archive`, 30 MB cap, `kv:upload-manifest`); AgentOS `syncUploadsFromVAS` pulls unseen files through its own readUpload → detectSource → applyLoad, and PULSE `syncUploadsFromStation` feeds them to its own `handleFiles`. No ping-pong: both archivers check the manifest hash before posting. Each manifest file is decided ONCE per app (`state.syncedUploads` in cb-config / `S.relaySeen` in vas-state); AGENT_LIST skips the Ops-side relay (it flows via `/api/roster`), SES_* never travels; unrecognised formats (MTD tracker, manual stats) are skipped by design.
12. **VAS MTD maths comes from the rule book, not from judgement.** `specs/mtd_engine_rules.json` (Appendix A of the VAS MTD Reporting Engine spec v6.0) is the record; the operative subset is inlined in `nicks_code/index.html` as `MTD_RULES` because the app must run from `file://`. **Change both together** — `diagnostics/verify-engine-rules.mjs` fails on drift. The rules that most often look like bugs and are not: Courtesy/Nesting Actual Shifts are DIALLER-derived (talk>0 → 1) while Cuddle uses the HR register; dialling days come from the attendance register, not from every dated file; QA filters on Date of Call ONLY, keeps 0% scores, and totals as a mean of agent means; CB67/CB205/CB265 are excluded by a maintained list that no data rule reproduces; ViciDial's `EXPORT_CALL_REPORT` (tab-separated .txt, one row per call) bills talk time as Σ`length_in_sec` grouped on the **`user`** column — the agent's CB number, never `owner`, which is blank on over half the rows — and that includes ringing, ~38% of the total, deliberately (Nick, 2026-08-13), reported on every upload and switchable via `viciCallReport.talkFrom`. V01–V22 re-run on every upload and print on the Data tab — never ship a figure with an error-severity FAIL. **A rule must be READ, not copied**: every gross-up goes through `MTD_VAT`, derived from `MTD_RULES.vat`, because the literal 1.15 scattered through the engine meant the VAT rule was drift-checked against the spec and used by nothing — editing it in both places would have passed every guard and moved not one rand. `diagnostics/verify-rule-constants.mjs` fails if any calculation grows its own copy again, and also holds the anonymous peer group to Σsales ÷ Σtarget (it published a mean of each agent's own percentage, so a two-day joiner weighed the same as a full-month agent, in the very figure an agent is shown on their own card).

## Dashboard conventions (when editing the HTML)

- Everything configurable lives in `DEFAULT_RULES` / `DEFAULT_KPIS` and is user-editable at runtime — never hardcode a threshold that belongs in a rule. Reference rules from KPI filters as `$ruleName`.
- Snapshot sources (`snapshot:true`) REPLACE on upload; time-series sources APPEND and window by `_d`. Two supersede exceptions in confirmLoad: ATTENDANCE (new file wins per employee-day) and BI_ACTIVE_CASES (new file wins for its own Contract-Create-Date span — months accumulate).
- All user strings through `esc()`; names through `maskName()`; money through `fmtVal(v,'zar')`/`zarStack()`.
- New data sources = new entry in `SOURCES` (header contract) + `TRANSFORM` (canonical mapping) + optionally KPIs. Rejected rows must land in exceptions with a reason.
- Persistence goes through `store()`/`load()` (async `window.storage`). On Cloudflare a localStorage shim is injected by `tools/prepare-site.js`; the target backend is a Worker API over D1/R2 (plan Phase 2) — don't scatter new persistence paths.
- ZERO-LOCAL constraint (user requirement): no local LLM, no local watcher/daemon, no local database. Compute/AI/cron/login = Cloudflare (Worker, Workers AI Hermes 2 Pro, Cron Triggers, Access); data = Supabase (Postgres SQL + Storage; brain vault syncs to Obsidian via Remotely-Save S3). The Worker is the ONLY thing that talks to Supabase — service-role key is a Worker secret, never in browser code, and CSP connect-src stays 'self'.
- Session snapshot slots (SES_*) never mix into daily analytics.

## Deployment (Cloudflare)

- `node tools/prepare-site.js` → regenerates `site/index.html` (injects storage shim).
- `/deploy` skill runs the full flow: prepare → verify → `npx wrangler pages deploy site`.
- **Before real data goes live: Cloudflare Access (Zero Trust) in front of the Pages domain.** Public URL + agent PII + campaign economics = POPIA incident.
- `site/_headers` carries the CSP — cdnjs.cloudflare.com must stay allowed (XLSX/Papa/Chart.js CDN) and `'unsafe-inline'` is required (inline script + onclick handlers).

## Workflows

- `/weekly-report` — score latest uploads → Monday TL brief into `reports/`
- `/upload-check <file>` — validate an export against source contracts before upload
- `/dashboard-fix` — conventions-aware editing of the dashboard
- `/deploy [prod]` — prepare + deploy to Cloudflare Pages
- `/nba-analyst …`, `/chatterbox-kb …` — global skills (installed in ~/.claude/commands)

## Subagents — delegate, keep main context clean

- `kb-agent` — Chatterbox KB questions (loads modules in its own context)
- `nba-scorer` — scoring/explain runs over data files (writes+runs scripts, returns results only)
- `dashboard-reviewer` — reviews HTML changes against the conventions above

The dashboard file alone fills most of a context window — never read it whole into the main session; Grep for the section you need or delegate to dashboard-reviewer.
